## InfoTeCS: Тестовое задание C++ "Многопоточная реализация записи в журнал"
### Библиотека liblogger.so
Библиотека для работы с классом Logger, отвечающим за запись в журнал.  
Инициализация Logger происходит через стандартный конструктор и параметрический - принимает путь к журналу и уровень важности. В случае вызова стандартного конструктора инициализирует "пустой" журнал с уровнем по умолчанию. В последствии изменить параметры можно через внутренний функционал.  
Выполнение команд записи и изменения параметров добавляются в очередь, которая освобождается в отдельном потоке. Получение происходит при вызове. Для синхронизации применяются мьютексы и атомарные операции, реализованные средствами mutex и atomic соответственно.   
Записывает сообщения не ниже установленного уровня.  
  
Список уровней:  
1. DEBUG - отладочный уровень
2. INFO - информационный уровень
3. NOTICE - уровень уведомлений
4. WARNING - уровень предупреждений
5. ERROR - уровень ошибок
6. CRITICAL - уровень критических ошибок
  
Для обработки ошибок предусмотрен следующий их список:
1. Ok - успешное выполнение
2. JournalUnspecified - не указан путь журнала
3. JournalNoopen - невозможно открыть журнал
4. LevelUnknown - неизвестный уровень важности
5. LoggerNullptr - случаи нулевого указателя Logger
6. Fatal - другая непредвиденная ошибка
  
Связанные файлы:
```
./src/lib/logger.cpp
./src/lib/logger.h
```

### Класс Test
Класс для проведения тестов над функционалом liblogger.so  
Принцип работы:
```
для трех имен журнала
  установить соответствующий путь журнала
  проверить соответствие устанавливаемого и установленного путей
  для всех уровней важности журнала
    установить уровень важности записи в журнал
    проверить соответствие устанавливаемого и установленного уровней
    для всех уровней важности сообщения
      попытаться записать сообщение в журнал
```
Связанные файлы:
```
./src/test.cpp
./src/test.h
```

### Древо autotools (Makefile) проекта  
``` ./Makefile ```  
Основной Makefile проекта  
Для сборки запускает ``` ./src/Makefile ```  
Имеет цели ```run-debug``` и ```run-release``` для быстрого запуска тестового и основного приложений соответственно   
  
``` ./src/Makefile ```  
Файл сборки приложения и перемещения в ```./build/```  
Обращается в ```./src/lib/Makefile``` для предварительной сборки библиотеки  
  
``` ./src/lib/Makefile ```  
Файл сборки библиотеки и перемещения в ```./build/```  
  
``` ./make.cfg ```  
Конфигурационный файл, используемый остальными  
  
```%-debug ``` и ```%-release``` цели:  
Общие постфиксы для работы с тестовым и основным приложениями соответственно  
```build%-debug``` - сборка TEST версии приложения  
```build%-release``` - сборка основной (финальной) версии приложения
